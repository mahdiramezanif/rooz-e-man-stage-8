# روزِ من — نسخهٔ ۸

این پروژه یک برنامهٔ فارسی و راست‌به‌چپ برای اندروید است. فایل اصلی وب (`index.html`) و رابط داخل اپ اندروید از یک کد استفاده می‌کنند. داده‌های برنامه‌ریزی، یادآوری، سبد کارها، دل‌نوشته‌ها، ورزش و زبان در حافظهٔ دستگاه (IndexedDB) ذخیره می‌شوند. دادهٔ شخصی با انتشار کد در GitHub آپلود نمی‌شود.

## امکانات نسخهٔ ۸

- صفحهٔ خانه با تاریخ شمسی، خلاصهٔ کارهای امروز و میان‌بر شش بخش اصلی
- نوار ناوبری ثابت موبایل و فهرست «بیشتر» برای خاطرات، ورزش، زبان، اعلان‌ها و پشتیبان‌گیری
- حفظ برنامه‌ریزی هفتگی شمسی، یادآوری‌های تکراری، سه سبد کار، دفتر خاطرات، ورزش و زبان
- هشدارهای آفلاین از طریق بخش بومی اندروید (با مجوزهای لازم)
- پشتیبان JSON با نسخهٔ ۸؛ خواندن پشتیبان نسخه‌های قدیمی هم پشتیبانی می‌شود
- Workflow ساخت APK بدون وابستگی به اسکریپت قبلی

## مشکل «در Actions هیچ workflowای نیست»

**مهم:** فایل موردنیاز با نقطه شروع می‌شود و هنگام آپلود از رابط وب GitHub ممکن است فراموش شود. در صفحهٔ Code مخزن، در **ریشهٔ شاخهٔ پیش‌فرض** مطمئن شو که این مسیر را داری:

```
.github/workflows/build-apk.yml
```

اگر این فایل وجود ندارد، در همان مخزن:
1. روی `Add file` و سپس `Create new file` بزن.
2. در فیلد نام، **دقیقاً** `.github/workflows/build-apk.yml` را تایپ کن.
3. محتوای فایل با همین نام در این ZIP را کپی کن و در شاخهٔ پیش‌فرض Commit کن.
4. در `Settings → Actions → General` اگر Actions غیرفعال است فعالش کن.
5. تب `Actions` را باز کن، `Build Rooz-e-Man Android APK` و سپس `Run workflow` را بزن.

فایل `android/settings.gradle` نیز باید در مسیر **ریشهٔ مخزن / android / settings.gradle** باشد. اگر به‌جای آن `rooz-e-man-stage-8/android/...` می‌بینی، پوشهٔ اضافی را بردار و فایل‌ها را به ریشه انتقال بده.

## استقرار مطمئن از لینوکس روی هر مخزن GitHub

برای Ubuntu / Debian:

```bash
sudo apt update
sudo apt install -y git gh unzip rsync nodejs
```

اگر اولین بار است GitHub CLI را روی این لینوکس استفاده می‌کنی:

```bash
gh auth login
gh auth setup-git
git config --global user.name "Your Name"
git config --global user.email "your-email@example.com"
```

فایل ZIP نسخهٔ ۸ را در Downloads استخراج کن:

```bash
mkdir -p ~/rooz-v8
unzip -o ~/Downloads/rooz-e-man-stage-8.zip -d ~/rooz-v8
cd ~/rooz-v8
node tests/check.js
node tests/check_diary.js
node tests/check_activity.js
node tests/check_v8.js
bash publish-linux.sh https://github.com/USERNAME/REPOSITORY.git
```

به جای `USERNAME/REPOSITORY`، آدرس **مخزن جدید خودت** را وارد کن. مخزن باید حداقل یک Commit (مثلاً README اولیه) داشته باشد. اسکریپت مخزن را تازه کلون می‌کند، تمامی فایل‌های نسخهٔ ۸ و پوشهٔ مخفی `.github` را کپی می‌کند، تست‌ها را اجرا و `git push` می‌کند. هنگام ورود ممکن است مرورگر از تو تأیید بخواهد.

توجه: این اسکریپت فایل‌های موجود با نام‌های یکسان را بازنویسی می‌کند. اگر تغییرات شخصی در سورس داده‌ای، قبل از اجرای آن کپی بگیر یا در یک شاخهٔ آزمایشی اجرا کن.

## دریافت فایل APK

در صفحهٔ GitHub Actions، منتظر بمان تا job سبز شود. در صفحهٔ همان Run، بخش Artifacts را باز کن و فایل `rooz-e-man-v8-debug-apk.zip` را بگیر. داخلش فایل `app-debug.apk` است.

**نسخهٔ Debug برای آزمایش است.** APKهای Debug ساخته‌شده در اجراهای مختلف GitHub ممکن است امضای متفاوتی داشته باشند؛ در نتیجه لزوماً نمی‌توانی نسخهٔ جدید را روی نسخهٔ نصب‌شده بدون حذف نصب کنی. **قبل از هر حذف، از داخل برنامه فایل JSON پشتیبان بگیر و سلامت آن را بررسی کن.**

## راه انتشار نسخهٔ امضاشده برای همکلاسی و به‌روزرسانی‌های آینده (اختیاری)

برای اینکه تو و همکلاسی‌ات بتوانید نسخه‌های بعدی را روی نسخهٔ نصب‌شده به‌روزرسانی کنید، از یک **کلید امضای ثابت و محرمانه** استفاده کن. این مرحله اختیاری است؛ اگر فقط می‌خواهی برنامه را امتحان کنی، Debug APK کافی است.

روی لینوکس `keytool` را نصب کن (در `default-jdk` است) و **یک بار** کلید شخصی بساز:

```bash
sudo apt install -y default-jdk
keytool -genkeypair -v -keystore rooz-signing.jks -keyalg RSA -keysize 3072 -validity 10000 -alias rooz
```

رمزها را در جای امن یادداشت کن. فایل `rooz-signing.jks` را **هرگز در مخزن GitHub بارگذاری نکن.** این فایل و رمزهایش را در جایی امن پشتیبان بگیر؛ گم‌شدن آن به‌روزرسانی نسخه‌های امضاشدهٔ قبلی را مشکل می‌کند.

محتوای base64 را با دستور زیر ایجاد کن (خروجی را عمومی منتشر نکن):

```bash
base64 -w 0 rooz-signing.jks
```

در مخزن GitHub به `Settings → Secrets and variables → Actions → New repository secret` برو و این چهار Secret را تعریف کن:

| نام Secret | مقدار |
| --- | --- |
| `ROOZ_SIGNING_BASE64` | خروجی base64 کلید |
| `ROOZ_SIGNING_STORE_PASSWORD` | رمز فایل JKS |
| `ROOZ_SIGNING_KEY_ALIAS` | `rooz` |
| `ROOZ_SIGNING_KEY_PASSWORD` | رمز کلید (اگر متفاوت است) |

بعد Workflow را مجدداً اجرا کن. علاوه بر Debug، فایل `rooz-e-man-v8-signed-release-apk` نیز ظاهر می‌شود. از **همین APK امضاشده** برای نصب روی گوشی خودت و همکلاسی‌ات استفاده کن و نسخه‌های آینده را با همان کلید، `applicationId` و `versionCode` بالاتر بساز.

در هر گوشی، اطلاعات جداگانه و محلی هستند. APK و سورس برنامه هیچ خاطره‌ای یا یادآوری شخصی را به همکلاسی منتقل نمی‌کنند.

## نحوهٔ استفاده برای اولین بار

1. برنامه را باز کن؛ صفحهٔ **خانه** یک نمای کلی از کارها را نشان می‌دهد.
2. از کارت «برنامهٔ هفتگی» یا دکمهٔ `هفته` در پایین، کارهای دارای ساعت را ثبت کن.
3. برای اعلان مستقل، بخش `یادآوری` را باز کن و تاریخ/ساعت شمسی تعیین کن.
4. کارهای بی‌موعد را در `سبدها` قرار بده.
5. برای نوشتن، ورزش، زبان، صندوق اعلان و پشتیبان‌گیری از دکمهٔ `بیشتر` استفاده کن.
6. در نسخهٔ اندروید، بخش اعلان‌ها را باز کن و مجوزهای **Notifications** و **Alarms & reminders** را فعال کن. اعلان دقیق تحت محدودیت‌های اندروید است و در برخی گوشی‌ها تنظیمات باتری نیز تأثیر دارد.
7. برای ایمنی اطلاعات، مرتب از بخش پشتیبان‌گیری JSON خروجی بگیر و آن را در محلی امن ذخیره کن. فایل پشتیبان به‌صورت متن خوانا است و رمزگذاری اختصاصی ندارد.

## ساخت محلی روی لینوکس (اختیاری)

با Java 17، Android SDK (API 35 و build tools 35.0.0)، و Gradle 8.11.1:

```bash
cd android
gradle --no-daemon :app:assembleDebug
```

خروجی: `android/app/build/outputs/apk/debug/app-debug.apk` نسبت به ریشهٔ پروژه. اگر این ابزارها را نصب نکرده‌ای، روش GitHub Actions ساده‌تر است.

تست‌های Node پروژه، شامل بررسی سازگاری داده‌ها و چیدمان فایل‌ها، اجرا شده‌اند. رابط نسخهٔ ۸ با مرورگر آزمایشی در اندازهٔ موبایل و دادهٔ شبیه‌سازی‌شده بررسی شده؛ اما APK نسخهٔ ۸ روی گوشی واقعی ساخته و آزمایش نشده است.
